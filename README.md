# 唛头的QQ群插件（原关键词自动回复插件）

一个为 **AStrBot** QQ 机器人设计的关键词自动回复插件。
当群聊 / 私聊消息命中配置中的关键词时，自动回复对应内容。

> 📌 插件显示名：**唛头的QQ群插件**（`metadata.yaml` 的 `display_name`）。
> 所有管理指令统一以 **`reply`** 为触发词，例如 `/reply-add`、`/reply-del`。

---

## ✨ 功能特性

- 🔑 **关键词自动回复**：消息命中关键词即自动回复，支持群聊 + 私聊
- 📍 **生效群聊范围**：自动读取 bot 所在全部群聊，WebUI 下拉勾选「哪些群生效」，支持白名单 / 黑名单 / 全部群三种模式
- 🎯 **三种匹配模式**：`contains`（包含）/ `exact`（完全一致）/ `regex`（正则）
- 🧑‍🤝‍🧑 **群聊智能 @**：命中时自动 `@发送者`，私聊自动不 @
- 🛡 **非命令触发**：纯关键词监听，不抢占 `/` 开头的指令
- ⚙️ **WebUI 可视化配置**：通过 `_conf_schema.json` 在管理面板编辑
- 💬 **运行时动态管理**：直接用 QQ 指令增删规则，**无需进 WebUI**
- 📏 **列表显示自动换行**：`/reply-list` 每条规则占多行，长关键词 / 长回复不会被截断挤到屏幕外
- 💾 **持久化 + 重启不丢**：规则写入 KV 存储 + 本地文件双保险，自动兼容新旧版本
- 🔐 **权限控制**：可限定只有指定 QQ 号能管理规则

## 📦 安装

把整个文件夹放到 AstrBot 的插件目录，然后 **WebUI 重载插件**：

```
AstrBot/
└── data/
    └── plugins/
        └── astrbot_plugin_keyreply/
            ├── main.py
            ├── metadata.yaml
            ├── _conf_schema.json
            └── requirements.txt
```

> 💡 文件夹名（`astrbot_plugin_keyreply`）建议**保持不变**，便于后续更新覆盖；
> 你在管理面板里看到的插件名称则以 `metadata.yaml` 的 `display_name` 为准，即「唛头的QQ群插件」。

要求 **AstrBot ≥ 4.10.4**（弹窗交互所需；旧版降级方案见 FAQ）。

## 🚀 快速开始

### 方式一：WebUI 配置（可视化，★推荐）

进入管理面板 → 插件配置 → 找到本插件 → 找到「关键词回复规则列表」区域：

**添加一条规则的完整交互：**

1. 点击 **「添加更多」** 按钮
2. 弹出模板选择框 → 选 **「基础规则」**（只有三项的简洁版；需要备注就选「高级规则」）
3. 弹出**表单对话框**，里面正好 **三个输入框**：
   - **关键词**：触发回复的关键词（正则模式下填如 `^你好`）
   - **回复内容**：命中后回复的文本（多行文本框，可写长内容）
   - **匹配模式**：下拉选择 `contains`（包含）/ `exact`（完全一致）/ `regex`（正则）
4. 填完点弹窗里的确认 → 回到列表，能看到新条目（折叠标题显示「关键词: xxx」，一眼区分）
5. **最后务必点右下角「保存并关闭」** —— 只填不保存等于没加

> 💡 **列表里的每条规则都可展开编辑 / 右侧删除**，改完同样要「保存并关闭」。

> ⚠️ **版本要求**：「添加更多 → 弹窗」这个交互依赖 AstrBot 的 `template_list` 配置类型，
> 需 **AstrBot ≥ 4.10.4**。如果你的版本较旧（如 4.9.x），请把 `_conf_schema.json` 里的
> `rules` 从 `template_list` 降级为 `list + template_schema`（见文末「常见问题」），
> 仍是「添加更多 + 三字段」，只是少了模板选择那一步，功能完全一致。

**规则的数据结构**（这是前端保存到配置文件的样子，了解即可，不用手改）：

```json
[
  { "__template_key": "basic", "keyword": "你好", "reply": "你好呀~", "mode": "contains" },
  { "__template_key": "basic", "keyword": "^\\?", "reply": "输入 /help 查看帮助", "mode": "regex" }
]
```

> 插件代码会自动剥离 `__template_key` 内部字段，只读取 `keyword / reply / mode` 三项。

### 方式二：QQ 指令动态管理（★推荐，随时增删）

直接在 QQ 里发指令即可，立即生效、自动持久化：

| 指令 | 说明 | 示例 |
|------|------|------|
| `/reply-add <关键词> \| <回复> [\| 模式]` | 添加 / 更新规则 | `/reply-add 你好 \| 你好呀~ \| contains` |
| `/reply-del <关键词>` | 删除规则 | `/reply-del 你好` |
| `/reply-list` | 查看所有规则（多行，长内容自动换行） | `/reply-list` |
| `/reply-stats` | 查看命中统计 | `/reply-stats` |
| `/reply-groups` | 列出 bot 所在全部群聊（✅/🚫 标注是否生效） | `/reply-groups` |
| `/reply-group-add [群号]` | 把群加入名单（群里发不填群号 = 加当前群） | `/reply-group-add 123456` |
| `/reply-group-del <群号>` | 把群移出名单 | `/reply-group-del 123456` |
| `/reply-scope [模式]` | 查看 / 切换生效模式：`all` / `whitelist` / `blacklist` | `/reply-scope whitelist` |

> 💡 **指令触发词统一为 `reply`**（用 `-` 连接，如 `reply-add`），每个指令同时兼容
> `/reply_add` 下划线写法，两种都能识别。参数含空格时用 `\|` 分隔（竖线前后可有空格），避免歧义：
> `/reply-add 早上好 | 早上好呀，今天也要加油！ | contains`

- 重复添加**同一关键词**会自动**覆盖更新**（视为修改回复）
- 添加后**无需重启、无需进 WebUI 保存**，立即生效且重启不丢失
- 命中统计是累计的，删除规则不影响历史计数

## 📍 生效群聊（限定在哪些群自动回复）

> 默认 `all`（全部群都生效），和以前行为一致；只有你想限定时才需要动这里。

### 三种模式

| 模式 | 含义 | 名单的作用 |
|------|------|-----------|
| `all` | 全部群聊生效（默认） | 不参与判定 |
| `whitelist` | **仅**名单内的群生效 | 名单 = 允许列表 |
| `blacklist` | 名单内的群**不**生效，其余都生效 | 名单 = 屏蔽列表 |

私聊不受群名单影响，由「私聊是否生效」单独开关。

### 方式一：WebUI 面板里勾选（★推荐）

插件加载后会自动通过协议端读取 bot 所在的**全部群聊**，把「群号 - 群名」写进配置项的
**下拉选项**，于是面板里可以直接选群，不用手抄群号：

1. 插件配置页 → **「生效群聊模式」** → 选 `whitelist`（只让选中群生效）或 `blacklist`（屏蔽选中群）
2. **「生效群聊名单」** → 点「添加更多」→ 在下拉里选群（形如 `123456 - 我的群`）
3. 点右下角 **「保存并关闭」**

> 💡 自动读取依赖 **aiocqhttp（OneBot）平台 + 协议端已连接**。插件启动约 20 秒后拉取一次；
> 若面板里暂时看不到下拉，**重载一次插件**即可（或直接在 QQ 里发 `/reply-groups` 触发刷新）。
> 拉不到群时该项退化为手填输入框，功能完全不受影响 —— 群号可以在目标群里发 `/sid` 查看。

### 方式二：QQ 指令（立即生效，不用进面板）

```
/reply-groups              # 列出 bot 所在全部群，✅ 生效 / ➖ 未选中 / 🚫 已屏蔽
/reply-group-add 123456    # 加入名单（在群里直接发、不填群号 = 加当前群）
/reply-group-del 123456    # 移出名单
/reply-scope whitelist     # 切换模式；不带参数 = 查看当前范围
```

> ⚠️ 在 `all` 模式下加群不会有任何效果，指令会提示你先切到 `whitelist` / `blacklist`。

写入的名单会**同时**保存到面板配置和插件 KV，重启不丢；面板里也能看到指令添加的结果。

## 💾 持久化机制（为什么"添加"一定能生效）

规则存储采用 **双保险**，按以下顺序读写：

1. **插件 KV 存储**（`keyreply:rules`）—— 框架标准方式，需环境正常注入 `put_kv_data`
2. **本地 JSON 文件**（`data/keyreply_rules.json`）—— KV 不可用时的自动降级

加载时：**KV → 本地文件 → WebUI 配置**，谁有数据用谁。
保存时：**两者同时写**，任一成功即算成功。

启动时插件会自动探测当前环境的 KV 是否可用，并在日志中告知：

```
[keyreply] 规则存储: KV + 本地文件=/path/to/data/keyreply_rules.json
```

如果你的版本较旧、KV 不可用，会看到：

```
[keyreply] 规则存储: 本地文件=/path/to/data/keyreply_rules.json
```

**这种情况下添加条目会写入本地文件**，依然完全可用——这正是本版本重点解决的问题。

> 规则文件位置：默认在 AstrBot 数据目录下，名为 `keyreply_rules.json`，可随时手动编辑（改完重载插件即可）。

## 🔐 权限控制

编辑 `main.py` 顶部的 `ADMIN_IDS` 列表，限制谁能管理规则：

```python
# main.py
ADMIN_IDS: list[str] = ["123456789", "987654321"]  # 填你的 QQ 号
```

- **留空 `[]`**：不限制，任何人都能增删（仅建议个人调试使用）
- **填入 QQ 号**：只有列表内的用户能执行 `add / del`

## ⚙️ 全局配置项（`_conf_schema.json`）

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `match_mode` | string | `contains` | 全局默认匹配模式 |
| `at_sender` | bool | `true` | 群聊命中时是否 @ 发送者 |
| `cooldown` | int | `0` | 同一关键词冷却秒数（0 = 不限制） |
| `group_mode` | string | `all` | 生效群聊模式：`all` / `whitelist` / `blacklist` |
| `enabled_groups` | list | `[]` | 生效群聊名单（下拉选「群号 - 群名」或手填群号） |
| `private_enabled` | bool | `true` | 私聊是否参与自动回复 |
| `auto_sync_group_list` | bool | `true` | 启动时自动读取群列表并写入面板下拉 |
| `rules` | template_list | 见下 | 规则列表 |

默认内置示例规则：`你好 → 你好呀~`、`谢谢 → 不客气！`。

## 🔧 常见问题

**Q：添加规则后没反应？**
1. 检查日志是否打印 `✅ 已添加规则` —— 没打印说明指令没被正确识别，确认是用 `/reply-add` 且参数格式正确
2. 检查 `ADMIN_IDS` 是否限制了你的 QQ 号
3. 查看数据目录下的 `keyreply_rules.json` 是否生成 / 更新

**Q：重启后规则还在吗？**
在的。规则持久化到 KV + 本地文件，重启自动重载。

**Q：WebUI 里改了 rules，和 QQ 指令添加的规则会冲突吗？**
不会冲突。WebUI 规则与 QQ 指令规则会**自动合并去重**（同一关键词取指令版），全部生效，谁也不覆盖谁。

**Q：如何备份规则？**
直接复制 `data/keyreply_rules.json` 即可。

**Q：面板里「生效群聊名单」没有下拉，只有输入框？**
说明还没读到群列表。按顺序排查：
1. 平台是不是 **aiocqhttp**（OneBot）—— 只有它能调 `get_group_list`；`qq_official` 等平台请手填群号
2. 协议端（NapCat / Lagrange 等）是否已连接 —— 插件启动约 20 秒后才会拉一次
3. 在 QQ 里发 `/reply-groups`：能列出群就说明读取正常，**重载一次插件**后面板就会出现下拉
4. 群太多导致下拉很长？可以在 hint（右侧问号）里看「群号 = 群名」对照表，手填群号同样生效

**Q：加了群到名单，为什么没生效？**
`all` 模式下列表不参与判定。发 `/reply-scope whitelist`（只让名单内生效）或 `/reply-scope blacklist`（屏蔽名单内）后再试；`/reply-scope` 不带参数可查看当前模式。

**Q：机器人退群 / 进新群了要重配吗？**
不用。群列表每次插件启动都会重新拉取并刷新下拉；`/reply-groups` 也会即时刷新。已保存的名单按群号匹配，不受群名变化影响。

**Q：我的版本是 4.9.x，没有「添加更多」弹窗 / 点了没反应？**
这是版本差异：`template_list` 类型在 **4.10.4 才引入**。4.9.x 的前端不认识它，
会把 rules 渲染成一段 JSON 原文（就是之前的「未指定模板」样式）。
降级方法 —— 把 `_conf_schema.json` 的 rules 字段替换为：

```json
"rules": {
  "description": "关键词回复规则列表。点「添加更多」新增一条。",
  "type": "list",
  "template_schema": {
    "keyword": { "description": "关键词", "type": "string", "default": "" },
    "reply":   { "description": "回复内容", "type": "text", "default": "" },
    "mode":    { "description": "匹配模式", "type": "string", "options": ["contains","exact","regex"], "default": "contains" }
  }
}
```

改完重载插件即可。功能（添加 / 编辑 / 保存）完全一致，只是少了「选模板」这一步。
推荐还是升级 AstrBot 到 ≥ 4.10.4，弹窗体验更完整。
