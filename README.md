# KOOK 机器人指令桥

把 QQ 上的消息转发给本地运行的 KOOK 机器人，在 KOOK 频道里执行指令，并把结果回传 QQ。

```
QQ 用户 ──▶ AstrBot(QQ 机器人)
                │  HTTP POST /command  (127.0.0.1:8787)
                ▼
        KOOK 机器人（本地 index.js）
                │  复用原有指令逻辑
                ▼
        KOOK 频道（改名 / 邀请 / 卖货 / 分组管理…）
                │  回复文本
                ▼
        QQ 群收到执行结果
```

## 使用前：先改 KOOK 机器人

插件本身不实现任何指令，必须配合打过桥接补丁的 KOOK 机器人使用：

1. 用 `index.js`（或 `apply-bridge-patch.mjs` 生成的 `index.bridged.js`）替换原文件
2. `.env` 补上 `BRIDGE_PORT=8787`、`BRIDGE_HOST=127.0.0.1`
3. `npm start` 重启，看到 `🌉 QQ↔KOOK 桥接服务已启动` 即成功

自检：`curl http://127.0.0.1:8787/health`

## 插件配置

| 配置项 | 说明 |
|---|---|
| `bridge_url` | KOOK 机器人桥接地址，同机默认 `http://127.0.0.1:8787` |
| `bridge_token` | 必须与 KOOK 机器人 `.env` 里的 `BRIDGE_TOKEN` 一致 |
| `kook_guild_id` | 服务器 ID，留空自动取第一个 |
| `kook_channel_id` | 指令落地频道，必须在 `TARGET_CHANNEL_NAME` 名单内，留空自动找 |
| `default_kook_user` | 默认执行身份，如 `唛头#1367`；留空则每人必须先绑定 |
| `async_mode` | 建议开启，慢指令先回「已转发」再推结果 |
| `echo_to_kook` | 结果是否同时发一份到 KOOK 频道 |
| `timeout_sec` | 请求超时，建议 ≥60 |
| `admin_only` | 仅 AstrBot 管理员可用 |
| `allow_qq` | 额外放行的 QQ 号白名单 |

## 生效范围（群聊 / 私聊）

插件配置里的 **`private_only`** 控制机器人在哪些会话里响应：

| 设置 | 群聊 | 私聊 |
|---|---|---|
| `false`（默认） | ✅ 响应 | ✅ 响应 |
| `true` | ❌ 忽略（**静默，不回复任何内容**） | ✅ 响应 |

开启后群里发的指令会被完全忽略 —— 不转发给 KOOK，也不在群里回话，避免刷屏。
被忽略时只写一行 AstrBot 日志，不会打扰群里的人。

> 判定方式：优先读 `unified_msg_origin` 里的消息类型
> （`FriendMessage` 私聊 / `GroupMessage` 群聊 / `GuildMessage` 频道），
> 再看群号是否为空，最后兜底用 `is_private_chat()`。
> 频道消息（GuildMessage）**算作群聊**，不会被当成私聊放行。

不确定当前设置有没有生效？发 `kook状态`，最后两行会显示：

```
生效范围　　　仅私聊（群消息已忽略）
当前会话　　　私聊
```

改完配置记得**重载插件**才生效。

## 回复样式

插件默认把回复**渲染成一张卡片图片**发送：淡色渐变背景 + 白色圆角卡片 + 顶部主题色条 +
状态图标（对勾 / 叉 / 感叹号），比纯文本整齐。

状态与配色：

| 场景 | 图标 | 主题色 |
|---|---|---|
| 执行成功、绑定成功 | 绿色对勾 | 绿 |
| 指令失败、权限不足 | 红色叉 | 红 |
| 等待确认、超时 | 橙色感叹号 | 橙 |
| 提示、查询类 | 蓝色 i | 蓝 |

> 注意：图片里**不画 emoji**。中文字体（微软雅黑等）不含彩色 emoji 字形，
> 硬画会变成「豆腐块」，所以统一用几何图标表达状态，视觉上更工整。

**与 KOOK 端保持一致**：图片会还原 KOOK 回复里的 KMarkdown 样式 ——

| KMarkdown | 图片里的呈现 |
|---|---|
| `📂 ✅ ❌ ⚠️` emoji | 彩色 emoji（系统 emoji 字体渲染） |
| `**加粗**` | 加粗 + 更深颜色 |
| `> 引用行` | 左侧主题色竖线 + 淡色底 |
| ``` 代码块 ``` | 灰底块，保留对齐空格 |
| `• 列表项` | 原样保留 |
| `(met)xxx(met)` | 自动去掉（KOOK 的 @提及语法） |

emoji 字体自动探测：Windows `seguiemj.ttf` → macOS Apple Color Emoji → Linux Noto Color Emoji
（再找不到用 fontconfig 兜底）。**万一都没有，emoji 会降级成单色字形，不会变成方块。**

**尺寸完全自适应内容**：宽度在 360~660 之间按实际最宽行收敛（短回复不会撑成宽图），
高度由行数累加得出，没有上限 —— 内容多少行，图就多高，**不会截断、不会丢字**。

换行规则：

- 标题、正文、页脚**全部**参与换行（标题超长会自动折行，不会被裁掉）
- 超长不可断内容（长 URL / 长 ID / 长英文串）按字符强制切分
- 连续英文单词不会被从中间拆开；中文逐字换行
- 只有当内容多到高度超过 8000px 时，才自动逐级缩小字号（正常回复不会触发）

关闭图片（退回文本卡片）或换字体，在插件配置里改：

| 配置 | 说明 |
|---|---|
| `image_mode` | 默认 `true`；设为 `false` 退回文本边框卡片 |
| `image_font_path` | 留空自动探测字体；想换字体填绝对路径 |

字体探测顺序：Windows 微软雅黑 → macOS 苹方 → Linux 文泉驿 / Noto CJK。
**找不到 Pillow 或中文字体时会自动降级为文本卡片，不会导致插件失效。**
（如需图片，请在插件目录下 `pip install Pillow`，requirements.txt 已声明）

## 使用方法

### 绑定（需本人在 KOOK 确认）

首次使用必须绑定，且**必须本人确认**：

```
绑定 唛头#1367
```

流程：

1. 机器人去服务器成员里找「唛头#1367」
2. 找到 → 在 KOOK 里**私聊**他，问「是否允许绑定」
3. 本人在 3 分钟内回复「确定绑定」→ 绑定生效
4. 超时 / 回复「取消」→ 绑定失败

> 该 KOOK 账号必须先进入机器人所在的服务器，否则会提示「先进入频道后再使用本命令」。
>
> 绑定关系存在 KOOK 端的 `info.json`，**每个 QQ 号对应各自的 KOOK ID**，互不干扰。
> 一个 KOOK 账号被新 QQ 绑定时，会自动解除与旧 QQ 的绑定。

### 发指令

```
kook 要塞 小明#1234
kook 联盟 1厅 要塞 小明#1234
kook 邀请 打宝3=1
kook 分组列表
kook 卖货
kook 关厅 一厅
```

之后直接发指令：

```
kook 要塞 小明#1234
kook 联盟 1厅 要塞 小明#1234
kook 邀请 打宝3=1
kook 分组列表
kook 卖货
kook 关厅 一厅
```

| 命令 | 作用 |
|---|---|
| `kook状态` | 检查与 KOOK 机器人的连通性 |
| `kook菜单` | 拉一份功能菜单到 QQ |
| `kook服务器` | 列出服务器和频道 ID（填配置用） |
| `kook身份` | 查看绑定的 KOOK 身份、**身份组、是否管理员**（权限问题首选） |
| `解绑` | 解除当前 QQ 的绑定 |
| `绑定列表` | 查看所有 QQ ↔ KOOK 绑定关系 |
| `kook解绑` | 解绑当前 QQ 的 KOOK 身份 |

## 注意事项

- **QQ 上无法 @KOOK 用户**，请统一用「用户名#四位ID」，如 `小明#1234`。`@小明` 拿不到 mention 数据会识别失败
- **邀请 / 卖货 / 要塞**依赖「你当前所在语音频道」，桥接用绑定账号实时查询；没进语音频道会收到提示
- **`TARGET_CHANNEL_NAME` 的限制依然生效**，落地频道不在名单内指令会被静默忽略
- **绑定必须由本人确认**：QQ 上发起后，机器人会给该 KOOK 账号发私聊，本人回复「确定绑定」才生效，避免冒名绑定
- **权限是真实校验的**：桥接会查绑定账号在该服务器的身份组再走 `isAdmin()`，非管理员会被拦下
- **只有「菜单」能用、其余全被拒** = 权限判定失败，发「kook身份」看诊断：
  - `管理员身份组 [无]` → 服务器里没有名为 `ADMIN_ROLE_NAMES`（默认「服主」）的身份组，改 .env
  - `我的身份组 [无]` → 读不到该用户身份组，确认账号在服务器里
  - 两者都有但不匹配 → 在 KOOK 里给账号加对应身份组，或改绑有权限的账号
- 安全建议：同机部署保持 `BRIDGE_HOST=127.0.0.1`；跨机器务必设置 `BRIDGE_TOKEN`
